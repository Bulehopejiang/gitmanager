# 🐙 Git 管理器（Git Manager）

一个**图形化 Git 管理软件**：把常用 git 指令封装成按钮，支持本地仓库与 GitHub 远程仓库，
内置**版本回溯**功能，并实时展示实体仓库的文件结构。

- 纯 Python 标准库实现（tkinter），**零第三方依赖**，开箱即用
- 已通过 19 项自动化自测 + GUI 冒烟测试，操作可靠

---

## 功能总览（对照需求）

| 需求 | 实现 |
| --- | --- |
| 常见 git 指令封装成按键 | 刷新 / 状态 / 添加全部 / 提交 / 推送 / 拉取 / 版本回溯 / 切换分支 / 暂存 / 恢复暂存 / 查看差异 |
| GitHub 提交功能 | 提交对话框支持「提交并推送到远程」；Token 设置后自动注入认证 |
| 用户指定本地仓库地址 | 顶部地址栏输入本地路径，回车或点「打开 / 克隆」 |
| 输入 GitHub 仓库地址 | 地址栏粘贴 `https://github.com/...` 网址，自动克隆到本地（弹出选择保存位置） |
| 版本回溯 | 「提交历史」页签选中任意版本 → 检出到新分支 / 软回溯 / 硬回溯（带危险确认） |
| 输出实体仓库文件结构 | 左侧文件树实时显示目录结构，带变更标记：●已修改  +新增  ×删除  ○未跟踪 |
| 变更信息存进仓库文件夹 | 每次**打开/刷新**仓库，自动在该仓库自己的文件夹里更新「仓库变更信息.txt」（含时间/分支/变更列表/最近提交/分支列表），并自动加入本地忽略，不会污染版本库 |

### 其他亮点
- 所有 git 命令在**后台线程**执行，界面不卡顿，操作中按钮自动禁用防误触
- 提交对话框默认勾选「提交前自动暂存全部改动」，新手也能一键提交
- 底部深色控制台实时显示每次执行的 git 命令与结果，出错有明确中文提示
- **窗口获得焦点时自动刷新**：在编辑器改完文件切回本软件，变更立即显示，无需手动点刷新
- 「变更」页签可按文件添加 / 放弃修改；「差异」页签高亮显示增删行
- 自动记住上次打开的仓库，启动时恢复（失效则静默跳过）
- 打开/刷新仓库时，自动把抓取到的**变更信息**写入该仓库文件夹内的
  `仓库变更信息.txt`（仓库路径、时间、分支、变更列表、最近提交、分支列表），
  随时回到文件夹即可查看该仓库的最新状态；文件通过 `.git/info/exclude`
  自动忽略，不会出现在「变更」列表中，也不会被误提交

## 环境要求

- Windows / macOS / Linux 均可
- Python 3.8+（自带 tkinter，若直接使用.exe文件则可忽视此条目）
- Git 已安装并加入 PATH（https://git-scm.com）

## 启动方式

```bash
python git_manager.py                                  # 直接启动
python git_manager.py D:\myproject                     # 启动并直接打开本地仓库
python git_manager.py https://github.com/用户/仓库      # 启动并克隆 GitHub 仓库
启动Git管理器.bat                                      # Windows 双击启动
```

## 快速上手（1 分钟）

1. 双击 `启动Git管理器.bat`（或 `python git_manager.py`）
2. 地址栏输入本地仓库路径（如 `E:\gitmanager\demo_repo`）→ 回车
3. 「变更」页签查看改动 → 点「添加全部」→ 点「提交…」填信息提交
4. 需要同步到远程时勾选「提交并推送到远程」（首次需先配置 Token）

> **现成可玩**：`demo_repo/`（4 个提交、2 个分支、含未提交改动，已关联本地测试远程
> `test_remote.git`，可直接测推送/拉取）；`我的项目/`（1 个提交的极简示例）。

## 🔘 按钮说明（速查手册）

### 顶部工具条（3 个）

| 按钮 | 对应 git 命令 | 作用 |
| --- | --- | --- |
| **打开 / 克隆** | `git clone` / 打开 | 地址栏是**本地路径** → 直接打开该仓库；是 **GitHub 网址** → 弹出选择保存位置并克隆。回车键等价 |
| **初始化仓库** | `git init` | 把地址栏指向的普通文件夹变成 git 仓库（第一次用 git 管理该文件夹时点它） |
| **Token 设置** | — | 填写 GitHub 个人访问令牌，保存后推送/拉取自动带认证（保存在 `~/.gitgui_config.json`） |

### 快捷操作按钮（11 个）

| 按钮 | 对应 git 命令 | 作用 |
| --- | --- | --- |
| **🔄 刷新** | `status/log/branch/...` | 重新抓取文件树、变更、历史、分支，让界面跟上磁盘最新状态（窗口获得焦点时也会自动刷新） |
| **状态** | `git status -uall` | 把完整仓库状态输出到下方控制台（含忽略规则等细节，比页签信息更全） |
| **添加全部** | `git add -A` | 把所有改动（修改/新增/删除）放入暂存区，准备提交 |
| **提交…** | `git commit` | 弹出提交对话框：填提交信息、可选作者；默认勾选「提交前自动暂存全部改动」，可勾「提交并推送」 |
| **推送** | `git push` | 把本地提交上传到远程仓库（第一个远程；https 自动注入 Token） |
| **拉取** | `git pull` | 把远程仓库的新提交下载并合并到本地 |
| **版本回溯** | `reset` / `checkout` | 把仓库恢复到「提交历史」中选中的某个旧版本（三种方式见「版本回溯」一节） |
| **切换分支** | `git checkout` | 弹出分支列表，切换到选中的分支 |
| **暂存** | `git stash push -u` | 把当前所有改动（含未跟踪文件）临时收起来，工作区变干净，可随时恢复 |
| **恢复暂存** | `git stash pop` | 把最近一次暂存的改动原样放回工作区 |
| **查看差异** | `git diff` | 在「变更」页签选中文件后点它，在「差异」页签预览改了什么（绿=新增、红=删除；已暂存/未跟踪文件也能正确显示） |

### 页签内按钮（4 个）

| 按钮 | 对应 git 命令 | 作用 |
| --- | --- | --- |
| **添加所选**（变更页签） | `git add <文件>` | 只把选中的文件加入暂存区（想挑几个文件提交时用） |
| **放弃所选修改**（变更页签） | `git checkout -- <文件>` | 丢弃选中文件的未提交修改（⚠ 有确认弹窗，丢失不可恢复） |
| **⬅ 回溯到所选版本**（提交历史页签） | 同「版本回溯」 | 先选中历史里的一个版本再点它，弹出三种回溯方式：①检出新分支（安全）②软回溯（保留改动）③硬回溯（⚠ 永久删除之后的提交） |
| **切换到选中分支**（分支页签） | `git checkout <分支>` | 先选中分支列表里的一个分支，再点它切换 |

### 新手推荐操作顺序

```
改文件 → 刷新/切回窗口(自动刷新) → 查看差异(确认改对) → 添加全部 → 提交… → 推送
                                              ↓ 需要挑文件时
                                         添加所选 → 提交…
```

> **安全提示**：「放弃所选修改」和「硬回溯」是破坏性操作，虽有确认弹窗，但确认后**无法恢复**，重要内容请先推送或备份；「暂存」只是临时收走改动（可恢复），与「放弃」不同，可放心使用。

## 📝 如何把本地文件提交到本地仓库（新手必看）

**场景**：本地有个文件夹，里面是普通文件，想用 git 管理起来。

| 步骤 | 操作 | 说明 |
| --- | --- | --- |
| ① 放入文件 | 把文件放进文件夹 | 文件夹本身无需任何准备 |
| ② 初始化仓库 | 地址栏输入文件夹路径 → 回车 → 提示"还不是 git 仓库"时点「初始化仓库」 | 等价 `git init` |
| ③ 添加文件 | 点「添加全部」 | 等价 `git add -A`；文件树里 `○未跟踪` → 已添加 |
| ④ 提交 | 点「提交…」→ 填提交信息 → 点「提交」 | 等价 `git commit -m "说明"`；本地仓库**不要勾**推送 |

提交完成后：「提交历史」页签出现新记录，变更数归零，文件树恢复干净。

- **只提交单个文件**：「变更」页签选中文件 → 「添加所选」→ 提交
- **文件没出现在列表**：检查是否有 `.gitignore` 把它忽略了
- **文件树标记含义**：`○未跟踪` 新文件 / `●已修改` / `×已删除` / `+新增` 已暂存

## ☁️ 推送到 GitHub

1. 点「Token 设置」填入 GitHub 个人访问令牌
   （Settings → Developer settings → Personal access tokens，勾选 `repo` 权限）
2. 确认仓库已关联远程（克隆的仓库自带；本地仓库执行
   `git remote add origin https://github.com/用户名/仓库名.git` 添加）
3. 提交时勾选「提交并推送到远程」，或直接点「推送」

## ⏪ 版本回溯（三种方式）

在「提交历史」页签选中某个版本 → 点「回溯到所选版本」：

- **检出到新分支**（推荐，安全）：回到旧版本，当前工作不丢失
- **软回溯**：HEAD 指回旧版本，之后的改动保留在暂存区
- **硬回溯**：⚠ 永久删除该版本之后的提交与工作区改动，需二次确认

## 支持的文件类型

| 类型 | 差异显示 |
| --- | --- |
| **文本文件**（.py .c .h .v .sv .txt .md .json .xml .yaml .ini .cfg .csv .tcl .asm .mif .qsf .sh .bat .log …） | 逐行对比：绿=新增、红=删除、蓝=位置标记 |

## 安全说明

- GitHub Token 保存在本机 `~/.gitgui_config.json`（明文，请勿分享该文件）。
  可用环境变量 `GITGUI_CONFIG` 指定其他保存位置。
- 推送时 Token 仅通过 HTTPS URL 注入本次命令，不会写入仓库配置。
- 硬回溯 / 放弃修改均为破坏性操作，软件已加确认弹窗；建议重要仓库先推送或备份。

仓库关联：git remote add origin https://github.com/用户名/仓库名.git
